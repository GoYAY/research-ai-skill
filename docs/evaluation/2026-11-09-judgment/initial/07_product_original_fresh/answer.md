建议今天把方向定为：**面向心理学研究生、以“必要时追问，条件够就推进”为核心的科研协作 Skill。** 第一版聚焦问卷量化研究，解决方法选择、采集准备和结果解释三个节点的问题。

你的三个困扰有一个共同点：AI 没有判断清楚，**哪些信息会改变当前决定，以及这些信息最晚什么时候必须确认。** 这应当成为产品的核心能力。

**1. 产品定位：帮助研究生把科研决策做对、做顺**

暂定名：**研伴｜心理学科研协作 Skill**。

一句话介绍：

> 根据研究目的和当前阶段，识别真正影响下一步的缺口，提出必要问题，并给出可以继续完成的工作。

首批用户建议聚焦：**正在独立开展第一项或前几项问卷量化研究的心理学研究生。** 先支持横断面问卷与两时点追踪，便于用有限场景覆盖你的三个痛点。

用户需要感受到的价值是：

- 推荐方法前，AI 先弄清楚自己想回答什么。
- 开始收数据前，AI 帮自己发现之后难以补回的信息。
- 写结果时，AI 给出与研究证据相符的表达。
- 已经说清楚的内容，AI 能接着用，不重复访谈。

这里的产品假设是：**用户愿意接受少量、解释得清楚的追问，换取更少返工。** 第一轮验证应重点检验这个假设。

**2. 核心功能：一张研究卡片，三个介入节点**

| 功能 | 触发条件 | 具体产物 |
|---|---|---|
| 研究卡片 | 开始协作或研究信息变化 | 记录目的、阶段、设计、变量、分析单位、已确认事项和待确认事项 |
| 方法选择前澄清 | 不同目的会改变设计或分析 | 必要问题，以及对应的分析路径和适用条件 |
| 采集前检查 | 用户准备发放问卷或开始追踪 | 与当前目标有关的数据字段、记录要求和待验证项 |
| 结果解释校准 | 用户提供统计结果或结论草稿 | 可直接使用的结果表述，以及需要调整的主张 |

研究卡片应由用户查看和修改。第一版通过对话内更新、导出后下次带入来衔接，不依赖跨会话自动记忆。

检查项可以参考 APA JARS–Quant 对研究目的、设计、测量、采集和分析信息的要求，再按当前任务选择相关内容。[APA 量化研究报告标准](https://www.apa.org/pubs/journals/releases/amp-amp0000191.pdf)

**最重要的功能规则，是决定何时提问：**

- **缺口会改变当前决定：** 说明影响，提出最少必要问题。
- **缺口只影响部分工作：** 暂缓依赖它的部分，继续其他工作。
- **信息已经足够：** 直接完成任务。
- **只有新事实、目标变化或进入新的依赖步骤时，才重新检查。**

每次追问尽量带上用途。例如：

> “你想比较两次调查的总体均值，还是同一个人的变化？这会决定是否需要跨时间匹配参与者。变量清单可以先整理；如果要研究个人变化，需要在首次采集前确认匹配方案。”

不设“最多追问三次”这样的硬上限。减少无用问题，靠的是判断问题是否改变下一步。

**3. 用一个完整场景贯穿第一版**

用户说：

> “我想研究研究生压力对睡眠的影响，用什么统计方法？”

Skill 先判断“影响”的含义是否清楚：用户想了解关联，还是希望评价减压干预能否改善睡眠？这个区别会改变研究路线，值得澄清。

如果用户确认只是一次问卷中的关联研究，就继续整理变量与分析条件，不再反复询问因果目标。

如果用户随后改成两时点、研究同一个人的变化，Skill 应在首次采集前检查跨时间匹配方式、测量时点和计分信息；匹配可以使用适当的研究编号，无需默认收集真实姓名。

当用户提供结果并写“压力导致睡眠变差”时，Skill 根据已有设计改写为与证据相符的表述。若数据已经收完才发现无法匹配，就明确当前还能回答哪些问题，并据此推进分析。

这个场景能够展示产品的连续协作能力，也适合成为你的项目演示主线。

**4. 第一版 MVP：先交付可重复使用的协作流程**

建议首版范围如下：

| 项目 | 第一版安排 |
|---|---|
| 研究范围 | 横断面问卷、两时点问卷追踪 |
| 输入 | 自然语言目的、设计草案、变量说明、数据字典、统计结果摘要 |
| 输出 | 研究卡片、分析建议、采集前检查单、结果解释 |
| 使用方式 | 在支持 Skill 的现有 AI 环境中调用 |
| 首版暂缓 | 自动运行统计软件、复杂实验与多层模型、文献库、多人协作后台 |

开发交付物控制为：

1. 一个 `SKILL.md`，定义触发条件、提问规则、推进规则和停止规则。
2. 三个简短模板：研究卡片、采集前检查单、结果解释。
3. 一组场景案例，检查它是否既能发现关键缺口，也能在信息足够时直接工作。

首版检查单也要区分**设计上已考虑**与**实际记录能力已验证**。例如，两时点研究需要匹配编号时，应安排用模拟记录检查导出后能否正确匹配，再开始依赖该功能的真实采集。

**5. 验证方案：同时检查“漏问”和“多问”**

先设计 **6 组成对场景，共 12 个案例**。每组保持任务相近，只改变一项关键条件：

- 目的含糊／目的已经明确。
- 追踪研究缺少匹配方式／匹配方式已确认。
- 采集前发现缺口／采集后发现缺口。
- 结论超出证据／结论与证据匹配。
- 只要求排版／要求判断研究方案。
- 延续已确认方案／新增事实改变方案。

用同一模型、相同输入，比较普通对话与启用 Skill 的表现。重点记录：

| 评价项 | 判断依据 |
|---|---|
| 必要问题是否问到 | 缺口是否会改变当前决定，是否及时发现 |
| 是否增加无用追问 | 是否重复询问，或追问与任务无关的信息 |
| 是否保留工作进度 | 等待回答时，能否完成独立部分 |
| 解释是否准确 | 研究设计、统计结果与结论是否匹配 |

再邀请 **3—5 位目标用户**，用去标识化材料或模拟任务试用，了解哪些追问值得回答、哪些打断了工作、是否愿意在下一阶段继续使用。人数是首轮验证建议。

**今天建议定下的是：目标用户、三个节点、按需追问规则，以及问卷研究的首版边界。** 后续先做场景原型和对照验证，再扩功能。

作为你的 AI 产品项目，最值得展示的成果将是：**你如何把科研协作中的判断问题转成产品规则，以及这些规则怎样改变用户完成任务的过程。** 这比单独展示一份长提示词，更能体现产品设计能力。
